# GeoRetail Agent 产品需求文档

版本：MVP 1.0｜2026-11-09｜状态：可运行的本地作品集原型

## 1. 产品背景与问题定义

GeoRetail 面向虚构连锁咖啡品牌 CoffeeLab，连接经营诊断与拓店初筛。项目从 GeoGPT 的专业 GIS 工具扩展业务流程，不将空间工具本身等同于产品价值。以下痛点均为待验证的场景假设，未进行真实企业访谈，也没有合作客户或可宣称的降本增效成果。

经营人员可能需要跨表整理经营记录、统一不同时间及店龄口径；拓展人员可能需要把经营观察转译为空间评价条件，再解释候选区域取舍。重复工作发生在口径确认、工具操作与证据整理之间。产品用显式参数、确定性工具、人工确认和可追踪报告，降低这条链路的操作门槛。

| 方案 | 优势 | 主要边界 | 本产品借鉴 |
| --- | --- | --- | --- |
| 传统 BI | 稳定指标与看板 | 跨 GIS 临时任务需额外开发 | 固定口径、排名及趋势 |
| 固定 Python 脚本 | 计算可复现 | 使用者需理解参数、文件和环境 | 保留计算内核及测试 |
| GIS 软件 | 空间分析专业 | 经营分析上下文及业务解释需人为衔接 | 专业能力封装为工具 |
| 受控 Agent | 解析临时问题、组织工具和解释证据 | 模型不可靠、需要边界与确认 | 只让模型解释需求，不计算数值 |

为什么需要 Agent：长期愿景是支持临时业务问题和跨工具规划，减少用户记忆专业工具参数的负担。当前离线 MVP 只是有限语法解析加固定工作流，固定脚本足以完成预定义演示，不能作为通用 Agent 自主能力的证据。在线可选模式仅用模型解析参数，后续步骤仍受状态机控制。GIS 是整条业务链中的专业分析模块，不能代替经营口径、策略确认和实地核查。

## 2. 目标用户与任务故事

### 角色 A：区域经营分析人员（场景假设）

作为经营分析人员，我希望用明确的指标比较完整经营窗口内的成熟门店，以便快速形成可复核的差异分析。触发：月度经营复盘。输入：月份、经营指标、门店范围。成功：排名口径透明、样本数量可见、能够查看门店明细并导出报告。

路径：总览查看趋势 → 提问最近六个月成熟门店利润率 → 核对利润及成熟定义 → 确认执行 → 查看 Top10、店型/商圈分组、竞品与交通特征 → 将已确认分析交给拓展流程。异常：时间不明时澄清，数据缺失时停止，不完整门店排除并提示数量。

### 角色 B：门店拓展专员（场景假设）

作为拓展专员，我希望把历史观察作为待验证线索，手动确认距离约束与评分权重，以便筛出最多三个值得进一步考察的候选商圈，而不是把历史相关性当成开店结论。触发：区域拓展初筛。成功：每个候选均满足硬约束、排名依据能解释、风险和不可用数据清楚。

路径：阅读经营摘要 → 修改目标区域/门店间距/交通上限/竞品上限 → 设置服务半径和权重 → 确认策略 → 地图与列表选择候选 → 对比指标/覆盖重叠 → 调整重跑或导出。无结果：显示各条件排除计数，返回策略页；少于三个：返回真实数量。

后续验证方案：邀请2—3位具有零售分析或拓展经验的参与者做合成数据可用性任务，记录口径理解、操作错误、任务完成和解释信任度；不将同学反馈冒充企业调研。

## 3. 产品目标与非目标

目标：降低经营与 GIS 操作门槛，支持可验证的自然语言需求、跨经营/GIS 工具任务、候选解释、异常反馈和分析记录。MVP 采用 Pandas 计算；SQL/DuckDB 是可替换的数据访问层，当前没有实现动态 SQL 执行。

非目标：预测真实新店收入/利润、自动签约开店、代替市场尽调、从相关性推出因果、在缺少数据时补造结论。没有真实经营数据与公开 GIS 数据接入，不输出上海真实商圈投资建议。

## 5. P0 功能详细需求

### FR-00 数据加载与指标查询

- 用户需求：先理解样本和时间覆盖，再查看总览。
- 前置条件：本地环境已安装，无需凭证。
- 输入字段：品牌 CoffeeLab、演示城市、总览最近1—12个月。
- 系统流程：固定种子生成五张表 → 标记 synthetic → 窗口过滤 → 汇总指标与趋势。
- 展示：数据来源、数据期、营业额/订单/利润/活跃店数、趋势、经营分布。
- 正常交互：修改窗口刷新总览；自然语言实际窗口在诊断页单独确认。
- 异常：经营工具发现缺失、非有限值、主键重复、财务不一致则停止并反馈。
- 数据依赖：Stores、StoreMonthlyMetrics；不读取原 inputdata 或私人文件。
- 验收：相同种子数据相同，四项KPI由窗口记录汇总，页面明确模拟来源。

### FR-01 自然语言经营分析

- 用户需求：分析最近6个月经营利润率最高的10家成熟门店。
- 前置条件：需求已解析，用户确认口径。
- 输入字段：months 1—12、metric、mature_only、top_n 1—50、city、end_month。
- 系统流程：规则/可选模型解析 → Schema → 确认 → 完整窗口/成熟过滤 → Pandas汇总排名。
- 展示：结构化参数、口径、实际窗口、排除数量、排名、明细和对比图。
- 正常交互：修改指标/月数/范围后点击确认执行；展示店型过滤不改变已执行分析。
- 异常：缺时间或指标要求补充；离线未知条件拒绝；无完整窗口/无增长前期则明确失败。
- 数据依赖：Stores、StoreMonthlyMetrics、LocationFeatures。
- 验收：利润率用汇总分子分母，降序稳定排序，同分按store_id；不以各月比率均值替代。

### FR-02 经营特征比较

- 用户需求：理解优秀门店在商圈、竞品、交通方面的共同特点。
- 前置条件：FR-01成功，优秀样本为当前Top-N。
- 输入字段：当前已确认排名及样本数。
- 系统流程：Top与其余样本比较 → 按店型/商圈分组 → 数值特征Pearson相关。
- 展示：样本数、商圈占比、分组汇总利润率、交通/竞争均值、相关系数、局限性。
- 正常交互：更改Top-N后重新执行；查看原始明细核对。
- 异常：对照为空或方差为零时显示不可用值，不补零；不声称因果发现。
- 数据依赖：排名与LocationFeatures。
- 验收：均值和样本数与明细一致；摘要声明模拟数据及混杂风险。

### FR-03 拓店策略生成与确认

- 用户需求：把观察转为待验证规则，自己决定硬约束和权重。
- 前置条件：已有已确认的经营分析。
- 输入字段：目标区域、门店间距下限、交通距离上限、竞品数量上限、半径、三项权重。
- 系统流程：展示分析证据和建议 → 用户修改 → 校验权重/范围 → 用户点击确认 → 记录策略快照。
- 展示：建议/默认假设与最终确认规则分开，数据可用性、固定评分锚点、缺失项说明。
- 正常交互：合计100%才允许提交，重新确认重算；参数编辑不会悄悄改变既有报告。
- 异常：负数、非有限值、超限、权重不为100拒绝；没有分析不可筛选。
- 数据依赖：分析摘要、候选和模拟POI可用性。
- 验收：后端与页面均有确认门槛；未确认不调用GIS；无效重提交清除旧候选确认状态。

### FR-04 GIS 候选商圈筛选

- 用户需求：找到符合规则的候选区域。
- 前置条件：FR-03有效并已确认。
- 输入字段：Strategy、注册的模拟图层与CRS。
- 系统流程：米制CRS/几何校验 → 目标区域过滤 → 最近店/交通距离 → 服务区POI计数 → 硬约束过滤 → 叠置覆盖 → 固定锚点评分 → 校验与Top-N。
- 展示：最多3个候选、每项距离/计数/评分/密度、约束满足标记和排除计数。
- 正常交互：修改参数再确认后重跑，结果与本次快照绑定。
- 异常：经纬度当米制、空图层、非法几何或工具失败中止；无结果说明计数可重叠并返回参数页。
- 数据依赖：Stores、CandidateSites、SyntheticPOIs，EPSG:32651。
- 验收：所有返回点满足全部约束，评分由代码计算；少于3个不补造。候选点无结果不代表连续空间无解。

### FR-05 候选结果解释

- 用户需求：对比指标，理解优势、风险及核查项。
- 前置条件：筛选完成且非空。
- 输入字段：候选ID和策略快照。
- 系统流程：选择候选 → 同步地图中心/高亮与右侧指标 → 输出规则解释。
- 展示：地图、Top-N、距离、三项分数、覆盖重叠、实地核查、CSV导出。
- 正常交互：下拉或地图点选更新当前候选；返回策略调整。
- 异常：无结果展示引导；地图CDN不可用提供不依赖地图服务的本地坐标散点视图。
- 数据依赖：已验证候选、模拟现有店和服务半径。
- 验收：选择更新详情，地图不把模拟坐标描述为真实门店；优势是规则匹配，不是收益承诺。

### FR-06 Agent 状态、错误与报告

- 用户需求：知道执行到了哪里、为何失败、如何复核。
- 前置条件：已创建任务，可为空任务。
- 输入字段：任务ID、阶段事件、耗时和结果。
- 系统流程：解析/确认/工具调用/校验记录事件 → 本地保存 → 报告及导出。
- 展示：状态、阶段耗时、工具结果数量、异常、来源、局限、已计算结果/统计关联/模拟假设/核查项。
- 正常交互：查看当前与会话历史、下载报告；重试要求再次点击确认。
- 异常：模型超时或无效JSON返回安全错误，可切离线；工具失败不展示旧结果、不无限重试。
- 数据依赖：工作流trace及结果快照，不记录原始问题/密钥/提供商响应。
- 验收：任务可关联报告和trace，文件位于单独过程目录；未完成内容不得写成完成。

## 6. 数据结构与指标口径

所有主键必填且唯一；月度表为复合主键。模拟表 source_type=synthetic。真实公开数据应记录 source_type=public、出处、许可和获取时间；用户导入应记录 source_type=user、归属及同意范围。后两类尚未接入，不混用或假称已有。下列坐标/财务/关联字段缺失时阻断；增长率、客单价、相关系数因分母或方差无效可为缺失，不填零。

| 实体 | 字段（类型及单位） | 关联与规则 |
| --- | --- | --- |
| Stores | store_id:string PK；name/brand/city/region/store_type:string；age_months:int（月，2025-12月末）；x/y:float（米）；lon/lat:float（WGS84度）；source_type:string | 店龄相对固定演示数据期，不随系统日期改变 |
| StoreMonthlyMetrics | store_id:string FK；month:string YYYY-MM；revenue/materials/labor/rent/other_cost/cost/profit:float（人民币元）；orders:int（单）；source_type | PK(store_id,month)，不生成开业前记录；财务精度0.01元 |
| LocationFeatures | store_id:string PK/FK；area_type:string；competitors:int（家）；transit_m:float（米）；source_type | 历史门店周边属性为独立模拟快照，非实时POI计算 |
| CandidateSites | site_id:string PK；name/city/region:string；x/y:float（米）；lon/lat:float（度）；source_type | 24个合成点；不是连续可用铺位或真实商圈多边形 |
| SyntheticPOIs | poi_id:string PK；kind:enum transit/competitor/demand；x/y/lon/lat:float；source_type | 220个合成设施点；仅用于演示GIS计算 |

营业额＝窗口收入之和；订单量＝订单之和；客单价＝窗口收入/订单，零订单不可用。成本＝材料+人工+租金+其他；经营利润＝收入−成本；经营利润率＝窗口总经营利润/窗口总收入，零收入不可用。经营利润不含未建模的完整税务、融资及资本开支，不是净利润。

同店前期增长＝同一门店当前窗口收入/紧邻等长前期窗口收入−1，要求两个窗口记录完整且前期非零。同比应比较上一年相同月份，但没有2024年数据，当前不计算同比。利润率可比性受店型/地区/成熟度影响；默认成熟过滤，提供分组结果，禁止把跨组差异包装为经营能力因果。

GIS计算采用EPSG:32651；展示坐标显式转换到EPSG:4326。最近距离为点到点欧氏距离；服务区为圆形多边形近似；POI密度＝服务区内需求点数/(πr²)，单位处/km²；覆盖重叠＝候选服务区与所有现有店服务区并集交集面积/候选服务区面积。

评分：需求分=min(需求点数/10,1)×100；交通分=max(0,1−交通距离/3000)×100；竞争分=max(0,1−竞品数/20)×100；综合分＝三项分×对应百分比权重之和。锚点10/3000/20、默认半径1000米、权重50/30/20均为可审查的演示假设，不是行业标定。半径与权重可编辑，固定锚点见代码，非收益模型。

## 7. Agent 产品与技术设计

受控单Agent工作流：READY → AWAITING_METRIC_CONFIRMATION → AWAITING_STRATEGY_CONFIRMATION → COMPLETED/EMPTY。参数不完整为NEEDS_CLARIFICATION；工具失败为FAILED。新问题清空下游状态；新策略提交前清空旧候选。确认只由用户按钮/显式演示CLI开关提供，模型Schema没有授权字段。

模型职责：把问题转成AnalysisRequest；未知指标/地点/条件应要求澄清。不执行代码，不选择文件路径，不计算财务、距离或评分。程序职责：Schema、计划顺序、排名/分组/关联、GIS、验证、保存报告。工具选择目前由固定阶段决定，仅查询指标与筛选参数动态变化；未实现任意工具自主规划。

复用决策：使用app.tool.base的BaseTool/ToolResult作为经营与GIS适配器合同；原app/Agent存在TSD二进制/重依赖，无法可靠整体启动，故采用与现有geosite一致的有限工作流机制，不迁移LangGraph。app.tool包改为惰性加载重模块，使基类可独立导入，保留既有公共名称。geosite.gis的buffer/overlay新增可选target，默认不变，避免上海数据套用原演示CRS，原测试回归验证兼容。

恢复策略：明确失败原因类别；允许修改参数/切换离线/修复数据后重试，无后台无限重试。缺少完整数据或前期则停止相关任务，模型不可用不自动伪装成在线成功。完成条件：经营分析、人工策略确认、GIS校验完成；空结果也是诚实的业务终态。

安全与成本：只读取合成数据，在线只发送问题文本；API凭证来自环境变量，不写入trace。现有历史曾有凭证暴露，应轮换；不使用也不重写Git历史。离线模型费用0，在线费用当前不计价，需查看服务商账单。产品限本机单用户，无鉴权或企业部署能力。

## 8. 产品验收与评测设计

下表为验收方法/目标，不是已测业绩；实际运行结果在TEST_REPORT。当前小样本只能验证工程链路，不能外推真实业务价值。

| 指标 | 计算方法 | 测试样本与验收条件 |
| --- | --- | --- |
| 参数解析准确率 | 全部关键字段匹配的合法问题数/合法问题数 | 支持语法与未知条件用例；离线已支持语法需100%匹配；扩展50条业务问题集尚未实施 |
| 完整任务成功率 | 输出经校验报告的完整任务数/有效预设任务数 | 核心案例CLI及UI各1次必须完成；空结果单独计业务终态 |
| 工具调用成功率 | 无错误工具调用数/总工具调用数 | 正常演示与故障注入分别统计，不把故障注入当线上稳定性 |
| GIS约束满足率 | 满足全部硬约束的返回点数/返回点数 | 独立距离/边界断言，目标100%；空结果无分母，不写100% |
| 计算结果正确率 | 与独立公式对照一致断言数/对照断言数 | 收入成本利润、汇总率、增长、排序、分组与关联；必须全部通过 |
| 完整耗时 | 从解析到导出perf_counter差值 | 本机演示记录实际值；不含用户思考与模型网络，阈值仅作回归参考 |
| 操作步骤 | 完成主流程的用户提交/页面切换次数 | 默认问题路径：解析→诊断→确认分析→策略→确认筛选→候选→报告，7个主要点击，另2次勾选 |
| 模型成本 | 实际token用量×服务商价格或账单 | 离线无API费用；在线未实网验收，不填假数 |

验收还要求五页正常/空状态、权重变化重算、候选选择、错误恢复、两次确认门槛与原GIS回归。浏览器地图点选和资源加载与AppTest覆盖范围必须分开记录。

## 9. 交互设计与迭代边界

统一深青导航、浅灰工作区、白色KPI卡、绿色主按钮、琥珀风险提示。业务术语优先，原型与MVP共用同一实现。页面说明见PROTOTYPE_GUIDE，业务和技术流见docs/flows。

后续优先验证用户口径理解、对解释的复核能力与无结果恢复；再开展合法真实数据接入、在线模型留出问题评测和路网分析。当前不能宣称自主Agent达到行业准确率，也不能将合成办公商圈高利润规律当作真实洞察。
