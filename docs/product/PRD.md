# GeoSite v2 最小产品需求

状态：本地合成演示可运行；真实业务产品尚未上线。

## 背景与用户假设

假设使用者为需要比较公共服务设施候选位置、缺少GIS操作经验的规划助理。没有真实访谈或真实用户数据。JTBD：给出距离约束后，查看哪些候选满足要求及推荐依据，调整偏好比较结果。

## MVP实现

P0：自然语言规则解析、米/公里归一、硬软条件分离、冲突/缺项提示、参数确认、固定工作流、统一CRS、精确距离筛选、加权排序、验证、地图/表格/报告和Trace。CLI可预确认；Web必须勾选确认。单约束查找的是合成候选网格，不是原始真实POI。

P1：四区域Web演示、44条离线评测、产品和求职材料。CLI提供可选真实模型Schema解析，MockTransport覆盖安全失败；真实服务商兼容性未实测。

## 交互和异常

输入明确演示需求 → 解析显示结构化字段 → 用户编辑米制距离/操作符/权重/Top-K → 勾选 → 执行 → 显示地图、Top-K、分项指标及导出。附近/未知城市/未知图层触发澄清；Schema非法拒绝；缺CRS/几何非法失败；合法空网格给出调整参数建议；失败可修改后重新执行（新run_id，非断点恢复）。不自动放宽硬约束。

## 数据依赖与验收

内置合成区域、医院、风险点和道路；不使用未知来源原始数据。每个推荐都须满足所有硬约束，原始指标/归一分数/权重可从JSON复算，工件存在且可读。对应tests/test_site_selection.py、test_workflow.py、test_web.py；实际通过情况见evaluation/REPORT.md和outputs/pytest.xml。

## 非目标与待开发

不是实际地块决策或审批系统；没有人口、地价、实时交通、法规RAG、真实城市数据接入、多人权限、跨进程恢复、取消长任务或自动重采样。UI参数编辑仍是JSON，非GIS用户可用性未经访谈验证；后续应换字段表单并测试。
